# Slotbound 稀有度概率 Mod（v1.3.1，适配游戏 v1.0.0(9)）

作者：**TokioKaze**（GitHub: [TokioKaze](https://github.com/TokioKaze)）

只修改“稀有度抽取概率”，游戏其他行为保持不变。仅供本地单人游玩。

## 一、游戏的实际抽取机制（从游戏代码确认）

| 来源 | 抽取方式 | 原版概率来源 |
|---|---|---|
| **局内老虎机**（图一） | 先判定本次转动是否中奖（符号连线、隐藏幸运/保底只影响“是否中奖”）；中奖后**每个召唤的单位单独抽一次稀有度**，按 普通/高级/稀有/传说/棱彩 权重加权随机（权重按总和归一化） | 局外研究：传说 0→0.1→0.2→0.4%，棱彩 0→0.02→0.05→0.1%，稀有 2/3/4.5%，高级 5/10/15%，其余为普通 |
| **命运石**（图二） | 每块石头有自己的一张稀有度表，加权随机；特殊石另有 15% “特殊单位”份额 | 每块石头固定表，例如裂隙石 90/0/0/9/1 |
| **命运石任务奖励 / 货架购买 / 开局携带的命运石** | 与上面相同（同一套石头表） | 同上 |

**解锁条件**：未购买“棱彩解锁”研究时，命运石的棱彩概率会被游戏并入传说；老虎机未解锁的稀有度权重为 0。

**不受本 Mod 影响、会叠加在修改后概率上的机制**：
- Joker 符号中奖固定得到“特殊”单位；教程中固定普通。
- 核心 JokerGrin：抽两次稀有度取较高者（用的是修改后的概率）。
- 核心 GoldenLever：黄金旋转中奖后稀有度再升一级（上限是“概率>0 的最高稀有度”）。
- 特殊大奖（specialJackpot5th）强制棱彩。
- 特殊石的 15% 特殊份额不变；目标概率按“除特殊外”的部分计算（日志会显示）。
- 沙盒模式使用自己的权重设置，不受影响。
- 隐藏幸运/保底（luck.lua 的 SbLuck/SbPity）只决定是否中奖，Mod 不改它。

## 二、受影响 / 不受影响的位置

- ✅ 局内老虎机稀有度（游戏内“稀有度”提示也会显示修改后的数值，方便确认）
- ✅ 所有命运石抽取（含任务奖励、货架、携带），命运石激活时的提示框
- ❌ 图鉴（收藏）界面里石头的“原始概率”展示可能仍显示原版数值
- ❌ 沙盒模式、Joker/教程固定结果、核心的额外效果（见上）

## 三、权重倍率 ≠ 最终概率

- **倍率模式**：原始权重 × 倍数后重新归一化。原版老虎机传说 0.4%，×5 后最终约 **1.97%**，不是 2%；
  裂隙石 传说9%/棱彩1% 各 ×5 后最终为 传说 **32.14%** / 棱彩 **3.57%**。
- **目标概率模式**：直接指定最终概率，其余稀有度按原相对比例分剩余部分。
  例：传说 10%、棱彩 5% → 普通/高级/稀有 按 80:15:4.5 分剩下的 85%（68.34% / 12.81% / 3.84%）。

日志 `SlotboundOddsMod.log` 会打印每处“原始 → 修改后”的最终概率。

## 四、安装

**推荐：免 Python 安装器**（Releases 里的 `SlotboundOddsMod_v*.zip`）
1. 完整解压，关闭游戏，双击 `SlotboundOddsModInstaller.exe`。
2. 安装器会从 Steam 库自动找到游戏目录（找不到就点“浏览…”），点 **安装 / 更新**。
3. 首次安装完成后，无需额外开启工具，之后直接从 Steam 启动游戏即可。

安装器有三个按钮：**安装 / 更新**、**恢复原版**、**检查安装状态**。

**从源码安装**（需要 Python 3）：`pip install cryptography` 后运行
`python slotbound_odds_patcher.py "<游戏目录>"`，或把仓库文件放进游戏目录后双击 `Install.bat`。

安装后游戏目录中：
- `Slotbound.dat` —— 已打补丁的游戏包
- `Slotbound.dat.orig` —— 原版备份
- `SlotboundOddsMod.ini` —— 配置文件（已有配置不会被覆盖）

**安装器的安全措施**
- 备份校验：安装和恢复前都会校验 `Slotbound.dat.orig` 能否用**当前** `Slotbound.exe` 解密、且不含 Mod。
  游戏更新后留下的旧备份不会被使用：当前文件是新版原版时自动重新备份；否则拒绝操作并提示用 Steam 验证完整性。
- 失败回滚：新文件先完整写入临时文件并回读校验，最后一步才替换 `Slotbound.dat`；备份用“复制”而不是“移动”。
  任何一步失败（游戏正在运行、磁盘已满、版本不符）时，原位置的 `Slotbound.dat` 保持不变。

## 五、使用

### 游戏内滑块面板（推荐）
- 启动后左上角会显示约 15 秒“概率 Mod 已加载 · 按 F8 打开稀有度设置”。
- **F8** 打开/关闭面板（Esc 也可关闭）。分两页：**局内老虎机**、**命运石**（用 < > 切换具体石头）。
- 每个稀有度一条滑条，**五项合计始终 100%**：拖高一个，其余按它们当前的相对比例自动降低；
  其余都被拖到 0 后再拖回，会按游戏原版比例分回。
- 滚轮或 ± 按钮微调 0.1%，按住 Shift 为 1%。滑条上的白色竖线是原版概率位置。
- 灰色的行是原版为 0 的稀有度（未解锁研究 / 该石头不产出），在 respect_unlocks = true 时不能调。
- 改动立即生效（老虎机下一次抽取、命运石下一次激活）。右上角“Mod 开/关”可随时切回原版对比。
- “恢复原版”恢复当前页；“保存到配置文件”写入 SlotboundOddsMod.ini，下次启动自动加载
  （面板保存会重写整个配置文件，原来的注释会换成简短说明）。
- 面板优先用系统的微软雅黑显示中文；读不到时用游戏字体，再不行显示英文。



### v1.3.1 更新
- **无限微调**（F7 开关）：游戏每用一次微调，Mod 立即清除“本波/本次旋转已微调”标记，可无限次微调（同一次旋转内也能连续微调）。
- **额外微调修复**：改为对比游戏自己的“当前波次 ID”（准备阶段按下一波算，与游戏一致）。额外次数用完后在同一波重新输入会立即生效，不用等下一回合；上一波留下的旧标记不会白白消耗次数。
- **必出小丑连线**（F7 开关）：小丑符号出现率在游戏代码里硬性封顶 5%（slot.lua 的 `math.min(0.05, …)`）。开启后，Mod 用游戏核心系统自带的 `forceJokerCells`（强制小丑格）机制，把每次旋转中间一行 3 格设为小丑；按游戏判线规则，3 个都是小丑的线会召唤“小丑”单位（特殊稀有度），从而解锁图鉴（discovery 键 `R1:J`）。核心原本强制的格子会保留。解锁后记得关掉。
- 日志：“幻影”等核心来回替换符号权重表时不再刷屏，相同组合只记录一次。

### 配置文件

1. 用记事本编辑 `SlotboundOddsMod.ini`，保存（UTF-8）。
2. 重启游戏。
3. 查看同目录 `SlotboundOddsMod.log`：
   - `已加载` —— Mod 已运行
   - `配置文件：…` —— 读取了哪个配置
   - `已挂接局内老虎机稀有度表` / `已应用到命运石` —— 修改应用到了哪里
   - `原始：… / 修改后：…` —— 实际概率
4. 进游戏把鼠标移到老虎机的“稀有度”图标上，提示里的数值即为修改后的概率。

配置错误（负数、超过 100%、合计超过 100%、非数字、无效模式等）时：出错的分区自动回退原版，并弹窗 + 写入日志说明原因。

## 六、卸载 / 恢复原版

任选一种（先关闭游戏）：
1. 安装器里点 **恢复原版**（源码方式：`RestoreOriginal.bat` 或 `python slotbound_odds_patcher.py "<游戏目录>" --restore`）。
   只有备份通过校验才会覆盖；备份失效时会提示改用方法 2。
2. Steam → 库 → Slotbound 右键 → 属性 → 已安装文件 → **验证游戏文件的完整性**。

只想临时关闭：把配置里 `enabled = false`，或在 F8 面板右上角关掉。`SlotboundOddsMod.ini/.log` 可直接删除。

## 七、游戏更新后

Steam 更新会覆盖 `Slotbound.dat`，Mod 随之失效（游戏照常运行）。之后需要重新适配：
- 新 exe 的密钥片段位置（打包器中的 `KEY_RVAS`）；
- `luck.lua` 是否还存在、完整性清单格式（SBIM001）、索引格式（SBIDX006 / SBDAT008）；
- 老虎机概率表路径 `constants.unitGrades.probabilities`、写入它的升级函数的写入顺序；
- 命运石模块 `src.game.stone` 的 `defs` / `effectiveProbs` 是否还在。

更新后直接重新运行安装器即可：版本仍被支持就会重新安装（并自动换掉旧备份），不支持则提示并停止，不会写坏文件。

## 八、技术说明（实现方式）

- 游戏为 LÖVE 11.5 + LuaJIT，代码在 `Slotbound.dat`（AES-256-GCM 加密，密钥由 exe 内置片段 + exe 的 SHA256 派生）；exe 会校验所有 DLL 的 SHA256，所以无法用替换 DLL 的方式加载 Mod。
- 补丁只替换包内 `src/game/luck.lua`：新内容是一个手写的 LuaJIT 字节码加载器，
  执行 `loadstring(Mod源码)(原luck字节码, ...)`；若 Mod 源码出错则直接运行原 luck 模块。
- 游戏有一条完整性哈希链：`main.lua` 内嵌 `release_integrity.lua` 的 SHA256 → `release_integrity.lua` 内嵌清单的 SHA256 → 清单记录每个文件的 SHA256。
  打包器自动沿链更新（luck.lua → 清单 → release_integrity.lua → main.lua），并自检包内不再残留任何旧哈希。
  （v1.0.0 漏了 main.lua 这一环，导致启动报 `integrity bootstrap mismatch`，v1.1.0 已修复。）其余 2068 个文件内容不变。
- 面板：在 `love.graphics.present` 前绘制，并包装 `love.handlers` 的键鼠事件（游戏自己的帧循环也走这两处）；面板内的点击不会传给游戏，面板出错会自动停用面板，不影响概率修改。
- 老虎机：把 `constants.unitGrades.probabilities` 变为代理表，游戏写入的原值存入影子表，读取时返回按配置计算的概率；游戏升级函数“先写 advanced、读回 advanced 算 normal”的过程中返回原值，保证原始概率正确。
- 命运石：包装 `stone.effectiveProbs`（游戏所有命运石抽取、卡包、提示都通过它，且在“棱彩并入传说”之后再计算），不修改原始石头表。
